# Bybit Mirror

Веб-зеркало одного Bybit-аккаунта для нескольких просматривающих. Бэкенд держит постоянное WebSocket-соединение с Bybit, хранит wallet+positions в памяти и стримит обновления всем подключённым браузерам в реальном времени.

Под капотом: **Go** (бэкенд) + **Svelte 5** (фронт). Без БД, без серверной сессии — всё in-memory. Один общий пароль на всех зрителей.

---

## Два пути запуска

| Путь | Кому подходит | Время | Нужны API-ключи |
|---|---|---|---|
| **1. Демо** | Просто посмотреть, как выглядит UI | ~2 минуты | ❌ |
| **2. Полное подключение** | Подключить свой Bybit-аккаунт | ~10 минут | ✅ |

---

## Путь 1. Демо за минуту

Не нужен ни Bybit-аккаунт, ни Go, ни конфиг — только Node.js. Покажет интерфейс с реалистичными синтетическими данными (5 позиций, 4 монеты).

**Что нужно:** [Node.js 20+](https://nodejs.org/).

```powershell
git clone https://github.com/p-repin/bybit_mirror bybit-service
cd bybit-service\web
npm install
npm run dev
```

Открой http://localhost:5173 → нажми **«Посмотреть демо без подключения»** под формой логина.

В шапке появится плашка «Демо-режим», вкладки «Активы» и «Позиции» наполнятся фейковыми данными. PnL подсвечен зелёным/красным, бейджи LONG/SHORT с плечом, всё как в боевом режиме — только данные не настоящие.

Чтобы выйти — кнопка «Выйти из демо» в шапке справа.

## Путь 2. Полное подключение к своему аккаунту

### Что понадобится

- **Go 1.22+** — [скачать](https://go.dev/dl/)
- **Node.js 20+** — [скачать](https://nodejs.org/)
- **Bybit API-ключ** (Read-only достаточно)

### Шаги

#### 1. Клонируй и зайди в папку

```powershell
git clone <repo-url> bybit-service
cd bybit-service
```

#### 2. Получи Bybit API-ключ

Зайди в свой Bybit-аккаунт → правый верхний угол → **Profile** → **API**.

Создай **System-generated API Key** с правами:
- ✅ **Unified Trading → Trade** (включает чтение wallet и position)
- Остальное опционально — нам не нужно

Без IP-whitelist для теста, или whitelist своего IP для прода. Скопируй `API Key` и `API Secret` — secret больше нигде не покажется, потеряешь — придётся пересоздать ключ.

#### 3. Скопируй конфиг и впиши данные

```powershell
copy config.example.json config.json
```

Открой `config.json` и заполни:

| Поле           | Значение                                                                |
|----------------|-------------------------------------------------------------------------|
| `environment`  | `mainnet` (боевой), `testnet` (тестовый), или `demo` (Bybit Demo Trading) |
| `region`       | пусто для глобального `bybit.com`; `eu`, `nl`, `tr`, `kz`, `ae`, `id` для регионов. **Если ключ создан на `bybit.eu` — обязательно `"eu"`** |
| `api_key`      | из шага 2                                                               |
| `api_secret`   | из шага 2                                                               |
| `cookie_insecure` | `true` для локального HTTP-теста; `false` для прода с HTTPS          |

`config.json` уже в `.gitignore` — твои ключи не утекут в коммит.

#### 4. Сгенери пароль для входа

```powershell
go run ./cmd/genpass МойПароль123
```

Утилита распечатает:
```
password_hash:  $2a$12$...
session_secret: c4cb8dc1...
```

Скопируй оба значения в `config.json` в одноимённые поля.

> `session_secret` — HMAC-ключ для подписи cookies. Если его поменять — все залогиненные слетят, придётся вводить пароль заново.

#### 5. Запусти бэкенд

В одном окне PowerShell:
```powershell
go run ./cmd/server -config config.json
```

Должно появиться:
```
INFO http listening addr=:8080
INFO bybit ws connected url=wss://stream-...
```

Если видишь `WARN bybit ws disconnected` — это нормально, ретрай поднимет (см. секцию «WebSocket» ниже).

#### 6. Запусти фронт

В **другом** окне PowerShell:
```powershell
cd web
npm install     # одноразово, ~30 секунд
npm run dev
```

Откроется на http://localhost:5173 → логинься паролем из шага 4.

## Запуск в проде

Подробности — в `CLAUDE.md`, секция «Деплой». Кратко:

```powershell
go build -o bybit-server ./cmd/server   # статичный бинарь
cd web && npm run build                  # статика → web/dist/
```

Дальше: nginx раздаёт `web/dist`, проксирует `/api/*` на `127.0.0.1:8080`. Go-бинарь крутится через systemd unit (Linux) или Windows Service. В nginx-конфиге обязательно `proxy_set_header Upgrade $http_upgrade` и `Connection "upgrade"` — без этого WebSocket не пройдёт.

## WebSocket и устойчивость

Сервис рассчитан жить долго и переживать обрывы:

- **Бэкенд → Bybit**: при разрыве WS ретраит с экспоненциальным backoff: 1с → 2с → 4с → ... → 30с (макс). На EU-эндпоинтах Akamai иногда флапает — обычно поднимается со 2-3 попытки. В логах: `WARN bybit ws disconnected ... retry_in=Ns`.
- **Браузер → бэкенд**: фронт авто-реконнектится по той же схеме. В шапке индикатор «Reconnecting…» — значит, WS лёг, идёт попытка.
- **При реконнекте** бэк сразу присылает свежий снапшот, никакого F5 делать не надо.

## Нюансы (про что точно спросишь)

### «WS подключился, а данные не идут»
Bybit шлёт `wallet`/`position` **только как дельты** — нет изменений на счёте, нет событий. Стартовый стейт приходит REST-снапшотом при подключении. Чтобы увидеть live-апдейт — переведи USDT в Unified, открой/закрой позицию, измени её размер.

### Один пароль на всех зрителей
Сервис рассчитан на «несколько глаз на один аккаунт». Все, у кого есть пароль, видят одно и то же. Это не баг, это фича. Различить пользователей в логах можно только по IP.

### Сколько живёт сессия
Cookie живёт 24 часа (настраивается `session_ttl_hours` в конфиге). После — снова ввод пароля.

### Мобилка / планшет
Работает, но без полировки: на iPad норм, на телефоне таблицы прокручиваются горизонтально (8 колонок физически не влезают). Адаптивный режим — в TODO.

### Безопасность
- Пароль защищён bcrypt (cost=12, ~250ms на проверку — это де-факто rate limit).
- Сессия stateless: cookie = `<random>.<expires>.<HMAC>`, проверяется по `session_secret` из конфига.
- API-ключ Bybit лучше иметь Read-only — даже если кто-то достанет конфиг, торговать не сможет.
- В проде обязательно HTTPS (за nginx) и `cookie_insecure: false`.

## Если что-то не так

| Симптом | Причина / фикс |
|---|---|
| `retCode=10003 API key is invalid` | Ключ невалиден или из другой среды. Проверь, что `environment` и `region` совпадают с местом, где ключ создавал. |
| Голый `HTTP 401` без JSON-тела на REST | Обычно: `region` не задан, а ключ из `bybit.eu` (или наоборот). Поправь `region` в конфиге. |
| `dial: context deadline exceeded` бесконечно | Network/DNS проблемы или Bybit-edge недоступен. Проверь, открывается ли `https://api-testnet.bybit.<region>/v5/market/time` из браузера. |
| Логин 401 «Wrong password» | Пароль не совпадает с тем, что генерил `cmd/genpass`. Сгенери заново и обнови конфиг. |
| Пустые таблицы после логина (на mainnet) | Подожди секунду — REST-снапшот может не успеть к моменту первого рендера. Обнови страницу. |
| Пустые таблицы после логина (на testnet) | На testnet-счёте может реально ничего не быть — возьми тест-USDT в фасете и переведи в Unified. |
| Фронт не видит бэк (`Failed to fetch` в консоли) | Бэкенд не запущен на `:8080`, или Vite-proxy не настроен. Vite-proxy уже прописан в `web/vite.config.ts` — просто запусти `go run ./cmd/server` параллельно. |

В корне есть скрипты `check_key.py` (CCXT REST) и `check_ws.py` / `check_ws_eu.py` (Python WebSocket) — для диагностики ключа без запуска самого сервиса. Запускать как `python check_key.py` (нужен Python и `pip install ccxt websockets`).
